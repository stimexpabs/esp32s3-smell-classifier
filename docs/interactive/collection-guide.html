Collecting the MQ-135 dataset

A worksheet for one recording session at the bench. Work down the page: prepare, check the signal range, record four rounds, verify. Then repeat on another day or in another room until every class has at least 24 events.

Ticks and values on this page are saved in this browser only. The recordings on disk are the real record; check_dataset.py counts them.

What you are recording

Four classes

The model learns to tell these apart from the shape of the sensor's response: how fast it rises, how high it goes and how slowly it falls.

clean

No gas.

Leave the sensor alone, or disturb the air without adding anything: a hand wave, a fanned card, moving the board.

breath

Exhaled air.

Breathe out slowly onto the mesh from about 5 cm. Recovers fastest, so it goes early in each round.

alcohol

Hand sanitizer or isopropyl alcohol.

A damp cotton swab held 2–5 cm from the mesh. Do not touch the sensor with it.

smoke

Incense, or a match just blown out.

Let the smoke drift across the mesh from 5–10 cm. Lingers longest, so it goes last in each round.

Alcohol vapour is flammable. Close the bottle and move it away before lighting anything, and record smoke in a ventilated room.

Step 1

Name the session and prepare

A session is one sitting: one place, one day, one warm-up. Whole sessions are later held back to test the model, so the name has to identify the sitting. Use a new name every time you sit down again.

Letters, digits and hyphens. Examples: d1-desk, d2-kitchen. Every command below uses this name.

Warm-up

The sensor needs at least 5 minutes powered before its reading settles. Start the timer when you plug the board in.

5:00 Not started.
Step 2

Check the signal range

Run the live monitor, note the clean-air value, then apply your strongest stimulus (usually alcohol, held close) and note the highest peak pin value. Stop the monitor with Ctrl+C.

.venv/bin/python tools/collect.py monitor

The ADC measures up to about 3100 mV at the pin. A response that reaches about 2900 mV flattens at the top, and flattened responses all look alike to a model.

Step 3

Record four rounds

Each command records two events. A round is one command per class, so no class sits only at the start or the end of the sitting, where the sensor's drift is different. Copy a command, follow the beeps, then tick the row.

What happens during one event

baseline10 s · keep clear
expose5 s
recover30 s or more · stimulus away, wait
1 beep: apply ▸2 beeps: remove ▸

Recovery lasts until the reading is back within 10% of the baseline, up to 3 minutes, and then the second event starts by itself. clean runs the same length with no beeps.

Air the room after every smoke run. Smoke that lingers leaks into whatever you record next.

Step 4

Verify the session

Count what is on disk and list the recordings worth redoing:

.venv/bin/python tools/check_dataset.py
FlagMeaningWhat to do
no-responseThe stimulus moved the reading by less than 15%.Delete the file and record again, closer.
contaminatedA clean recording moved by more than 15%.Delete it, air the room, record again.
clippedThe pin reached 2900 mV.Delete it and record from further away.
no-recoveryThe recording ended more than 10% above its baseline.Keep it. Wait longer before the next event.

Recordings are files named data/raw/<label>/<session>_<nn>.csv. To remove one, delete its file. Then look at the shapes:

.venv/bin/python tools/plot.py
  • Each panel is one class, with every event overlaid and time zero at the first beep.
  • clean should stay near 1.0. The other classes should rise after time zero.
  • If two classes look the same to you, the model will struggle with that pair. Rethink that pair before recording more.
Step 5

Repeat across sessions

Three sessions give 24 events per class, enough to train a first model. Five give 40. Use a different day or room each time, and a new session name.

If something goes wrong

Troubleshooting

The tool cannot open /dev/ttyACM0

Only one program can hold the serial port. Close the ESP-IDF monitor in VS Code (Ctrl+]) or any other collect.py that is still running.

"No data from /dev/ttyACM0"

The board is not running the data-logger firmware, or it is still booting. Unplug and replug the USB cable and try again. If it persists, flash firmware/data_logger again.

plot.py fails with "No module named matplotlib"

That terminal has ESP-IDF activated, which switches python3 to ESP-IDF's own environment. Open a new terminal without activating ESP-IDF and run the tool there.

The reading never comes back to the baseline

The room air still carries the gas. Open a window, move the stimulus further away and wait. The tool gives up after 3 minutes and warns you; let the monitor settle before the next run.

I applied the stimulus at the wrong time

Finish the run, then delete that event's file. The label would be wrong for the model, and a wrong label does more harm than a missing event.

The clean-air value is different from yesterday

That is normal. MQ sensors drift with temperature, humidity and age. The model works on each reading divided by its own baseline, and recording on several days teaches it the drift.
