Step 1

Hardware: how the sensor makes a voltage

PartWhereNotes
MQ-135 module, unmodifiedVCC to 5 V, GND to GNDAO reaches GPIO6 = ADC1 channel 5 through a 4.7k / 6.8k divider
BuzzerGPIO38passive, behind a transistor, driven by PWM
USB/dev/ttyACM0the chip's native USB port: power, flashing and console

The sensor is a tin-dioxide element kept hot by a 5 V heater. Its resistance Rs drops when alcohol, ammonia, smoke or solvents reach the surface. On the module, Rs and a load resistor RL form a divider across 5 V, and the output AO is the voltage across RL. More gas means lower Rs and a higher AO.

AO can approach 5 V and the ESP32-S3's ADC pin measures up to about 3.1 V, so the board scales it down with 4.7k over 6.8k. That divider also sits in parallel with RL, so the sensor works into a smaller load than the resistor printed on the module.

RL_eff = RL ∥ 11.5k
AO     = 5 V × RL_eff / (Rs + RL_eff)
V_pin  = AO × 68 / 115

On this board clean air sat between Rs ≈ 45 kΩ and 210 kΩ on the same evening. With the stock 2 kΩ load that is only 24 to 110 mV at the pin, which is why the firmware averages many ADC reads per sample.

Burn-in and warm-up

  • Once: leave a new sensor powered for 24 to 48 hours.
  • Every session: power the board for at least 5 minutes before recording or testing.

Step 3 · firmware explained

The data-logger firmware

A model is only as good as its data, so the first firmware does nothing but measure. It streams the sensor to the PC and marks the moments a stimulus is applied.

command taskwaits for a byte from the PC

Reading the ADC

firmware/data_logger/main/data_logger_main.c 
adc_oneshot_chan_cfg_t channel_config = {
    .atten = ADC_ATTEN_DB_12,
    .bitwidth = ADC_BITWIDTH_DEFAULT,
};
adc_oneshot_config_channel(adc, ADC_CHANNEL_5, &channel_config);

adc_cali_curve_fitting_config_t cali_config = {
    .unit_id = ADC_UNIT_1, .chan = ADC_CHANNEL_5,
    .atten = ADC_ATTEN_DB_12, .bitwidth = ADC_BITWIDTH_DEFAULT,
};
adc_cali_create_scheme_curve_fitting(&cali_config, &cali);
  1. Oneshot mode takes a reading when asked. At 10 Hz there is no need for the continuous, DMA-driven driver.
  2. 12 dB attenuation gives the widest input range, about 0 to 3.1 V, which covers the 2.96 V the divider can deliver.
  3. Calibration converts raw counts to millivolts using correction values burned into each chip at the factory. Without it two boards report different voltages for the same input.

One sample is 64 reads, on a steady clock

TickType_t last_wake = xTaskGetTickCount();
while (1) {
    int64_t t_ms = now_ms();
    int sum_mv = 0, reads = 0;
    for (int i = 0; i < OVERSAMPLE; i++) {            // OVERSAMPLE = 64
        int raw, mv;
        if (adc_oneshot_read(adc, MQ135_ADC_CHANNEL, &raw) == ESP_OK &&
            adc_cali_raw_to_voltage(cali, raw, &mv) == ESP_OK) {
            sum_mv += mv;
            reads++;
        }
    }
    int adc_cmv  = sum_mv * 100 / reads;                // hundredths of a millivolt
    int true_cmv = (int)((int64_t)adc_cmv * DIVIDER_TOTAL_OHM / BOARD_DIVIDER_BOTTOM_OHM);  // × 115 / 68
    ...
    vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(SAMPLE_PERIOD_MS));
}
  1. Averaging removes most of the ADC's noise and resolves well below its 1 mV steps. On the board the readings hold within about ±0.4 mV.
  2. Integers only. Values are carried in hundredths of a millivolt, so printing never needs floating-point formatting.
  3. vTaskDelayUntil wakes the loop every 100 ms measured from the previous wake-up. The time spent reading and printing does not add up as drift, and the model will assume evenly spaced samples.
  4. Why 10 Hz: the sensor responds over seconds. Ten samples a second capture a rise with room to spare and keep a 10-second window down to 100 numbers.

Markers and commands

static void command_task(void *arg)
{
    uint8_t c;
    while (1) {
        if (usb_serial_jtag_read_bytes(&c, 1, portMAX_DELAY) != 1) continue;
        if (c == '1') {
            buzzer_beep(BEEP_FREQ_HZ, BEEP_MS, 1);
            printf("M,%lld,1\n", now_ms());
        } else if (c == '0') {
            buzzer_beep(BEEP_FREQ_HZ, BEEP_MS, 2);
            printf("M,%lld,0\n", now_ms());
        }
    }
}
  1. A separate task sleeps inside usb_serial_jtag_read_bytes until a byte arrives, so waiting for commands costs the sampling loop nothing.
  2. The marker carries the board's own clock. Samples and markers share one timebase, so USB delays cannot shift a label relative to the data.
  3. One beep tells you to apply the stimulus, two to take it away.

The buzzer driver

firmware/components/buzzer/buzzer.c 
void buzzer_beep(uint32_t freq_hz, uint32_t on_ms, uint32_t count)
{
    esp_timer_stop(s_timer);          // replaces a pattern still playing
    s_freq_hz = freq_hz;
    s_on_us = on_ms * 1000;
    s_remaining = count;
    set_tone(true);                   // LEDC: set frequency, 50% duty
    esp_timer_start_once(s_timer, s_on_us);
}

static void step_cb(void *arg)        // runs at the end of every beep and pause
{
    if (s_sounding) {
        set_tone(false);
        if (--s_remaining == 0) return;
    } else {
        set_tone(true);
    }
    esp_timer_start_once(s_timer, s_on_us);
}
  1. A passive buzzer needs a square wave. The LEDC peripheral generates PWM; the PWM frequency is the pitch and 50% duty is the loudest point.
  2. No delays. A one-shot esp_timer ends each beep and starts the next, so buzzer_beep returns at once and a beep never holds up a sample.
  3. count is the number of beeps, which the inference firmware uses to say which class it heard.
Step 4

Collecting a dataset

Four classes, recorded by hand: clean, breath, alcohol and smoke. Each command records two events and saves one CSV per event:

.venv/bin/python tools/collect.py record --label alcohol --session d1-desk --events 2
PhaseDefaultWhat you do
baseline10 snothing; keep the sensor in clean air
expose5 sone beep: hold the stimulus near the sensor
recover30 s or moretwo beeps: take it away and wait
  • Sessions matter. A session is one sitting. Whole sessions are held back to test the model, so record at least three, on different days or in different rooms: 8 events per class per session.
  • Vary on purpose. Change the distance, the strength and the duration, and include clean recordings where the air is disturbed without a gas. The model learns whatever differs between the classes, and it should not be "2 cm for 5 seconds".
  • Check after each session with .venv/bin/python tools/check_dataset.py and .venv/bin/python tools/plot.py.

The bench procedure, with a round planner, a range check and a warm-up timer, is in the companion worksheet: MQ-135 Collection Guide.

Alcohol vapour is flammable. Close the bottle and move it away before lighting anything, and record smoke in a ventilated room.

Step 5

Preprocessing: from a recording to model inputs

The model looks at 10 seconds at a time: 100 samples. A recording is cut into many overlapping windows, and each is normalised using only what is inside it:

ref  = mean(v[0..9])                    the window's first second
x[i] = clip( ln(v[i] / ref), -1, 4 )    for all 100 samples
  • Dividing by ref removes the baseline. In the first session clean air fell from about 180 mV to 40 mV in 45 minutes, more than most of the responses being classified.
  • The logarithm compresses the range. Alcohol reached 29 times its baseline and breath about 1.2 times; on a log scale those are 3.4 and 0.2.
  • Only the window. The recording tools know when the stimulus started; the board never will. Anything computed from outside the window could not be reproduced on the device.

Step 6

Training a 516-parameter network

.venv/bin/python training/train.py
Input100 × 1one normalised window
Conv1D 8 × 596 × 8 · 48 paramseight small filters slide along the window: "rising fast", "falling slowly"
MaxPooling 248 × 8halves the length, keeps the strongest response
Conv1D 16 × 346 × 16 · 400 paramscombinations: "sharp rise then slow fall"
GlobalAveragePooling16how much of each pattern the window holds, wherever it occurs
Dense + softmax4 · 68 paramsone probability per class
  • Convolutions recognise a rise wherever it sits in the window, which matters because on the board an event can start anywhere.
  • Global average pooling replaces a large dense layer that would hold most of the parameters and learn where the training events happened to be.
  • Small on purpose. With a few hundred windows, a larger model would memorise them.

Testing it honestly

Overlapping windows from one event are near-copies. If some landed in training and others in testing, the test would measure memory. So whole events are held out together, and once three sessions exist, whole sessions are. With one session the figure below is optimistic, because training and test share a sitting.

Rows are what the window really was, columns what the model said. The diagonal is correct. Counted per event: 29 of 32 right.

  • Alcohol and smoke are separated mostly by size. The weakest alcohol event (3× baseline) was called smoke and the strongest smoke event (7×) was called alcohol. Size depends on distance, not on the gas.
  • Breath and clean overlap. Breath raises the signal by about 1.2×, and clean air drifted nearly as much.
  • Nothing strong is mistaken for clean. Detecting that something happened is the easy part.

The next sessions should therefore include weak alcohol from far away, strong smoke from close up, and breath held closer. If alcohol and smoke still cannot be told apart once their sizes overlap, the sensor does not carry the difference, and a class should be merged or dropped.

Step 7

Quantising to 8 bits and converting to C

.venv/bin/python training/convert.py

The trained model stores 32-bit floats. The board runs it with 8-bit integers: a quarter of the size, and the arithmetic microcontroller libraries optimise hardest. Every tensor gets a scale and a zero point that map real values onto the 256 levels of an int8:

real_value = scale × (int8_value − zero_point)

The converter chooses them by running 300 real windows through the model and watching the range of values in each layer. For the input it chose scale 0.014355 and zero point −108.

Setting up the interpreter

firmware/inference/main/inference_main.cc · model_init() 
const tflite::Model *model = tflite::GetModel(g_model_data);

static tflite::MicroMutableOpResolver<7> resolver;
resolver.AddConv2D();
resolver.AddExpandDims();
resolver.AddFullyConnected();
resolver.AddMaxPool2D();
resolver.AddMean();
resolver.AddReshape();
resolver.AddSoftmax();

static tflite::MicroInterpreter interpreter(model, resolver, s_arena, TENSOR_ARENA_BYTES);
interpreter.AllocateTensors();
s_input  = interpreter.input(0);
s_output = interpreter.output(0);
  1. GetModel reads the model in place from flash. Nothing is copied to RAM.
  2. The resolver lists the seven operators from step 7. Only these are linked into the firmware; leave one out and AllocateTensors fails at start-up.
  3. The tensor arena is a plain byte array holding every intermediate result. TensorFlow Lite Micro never calls malloc. The firmware gives it 16 kB and it used 3,836 bytes.
  4. C++. The library is C++, so this file is .cc and declares extern "C" void app_main(void).

From voltages to an answer

classify() 
float ref = 0.0f;
for (int i = 0; i < MODEL_REF_SAMPLES; i++) ref += v[i];
ref /= MODEL_REF_SAMPLES;

const float scale = s_input->params.scale;
const int zero_point = s_input->params.zero_point;
for (int i = 0; i < MODEL_WINDOW; i++) {
    float x = v[i] > 0.0f ? logf(v[i] / ref) : MODEL_CLIP_LO;
    x = fminf(fmaxf(x, MODEL_CLIP_LO), MODEL_CLIP_HI);
    long q = lroundf(x / scale) + zero_point;
    s_input->data.int8[i] = (int8_t)(q < -128 ? -128 : q > 127 ? 127 : q);
}

s_interpreter->Invoke();
memcpy(out, s_output->data.int8, MODEL_CLASS_COUNT);
  1. The same maths as step 5, line for line: reference from the first second, logarithm, clip.
  2. Nothing is typed in twice. MODEL_WINDOW, MODEL_REF_SAMPLES and the clip limits come from model_data.h, which convert.py writes from the constants in preprocess.py. The scale and zero point are read from the model. Retraining cannot leave the firmware out of step.
  3. The output is four int8 values. With scale 1/256 and zero point −128, a byte of 127 means a probability of about 1.0.
  4. A mutex guards the interpreter, because the sampling loop and the replay task both use it.

The main loop

app_main() 
float mv = sensor_read_mv();
s_ring[s_ring_next] = mv;
s_ring_next = (s_ring_next + 1) % MODEL_WINDOW;
since_infer++;

if (s_ring_count == MODEL_WINDOW && since_infer >= SAMPLES_PER_INFER) {
    since_infer = 0;
    for (int i = 0; i < MODEL_WINDOW; i++)                 // oldest sample first
        window[i] = s_ring[(s_ring_next + i) % MODEL_WINDOW];

    int64_t infer_us = classify(window, out);
    ...
    track_event(confident ? best : 0);
}
vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(SAMPLE_PERIOD_MS));
  1. A ring buffer always holds the newest 100 samples without moving any data. s_ring_next points at the oldest one, which the next sample overwrites.
  2. Unrolling copies the ring out oldest-first, so the model sees the window in the same order as a training window.
  3. Once a second is often enough for a signal that changes over seconds, and it keeps the processor idle 99.8% of the time.
  4. The first answer comes after 10 seconds, when the buffer has filled.

From predictions to events

The model answers once a second, and one answer is not an event. While a response is still rising, the window holds only its first second or two, which the model never saw in training. So the firmware waits and votes.

Try it · feed the event logic one prediction per second
IDLEVOTINGHOLD-OFF

A prediction below 60% confidence is treated as clean before it reaches this logic.

track_event() 
case IDLE:
    streak = cls != 0 ? streak + 1 : 0;
    if (streak >= START_STREAK) { /* clear votes */ state = VOTING; }      // 2 in a row
    break;

case VOTING:
    votes[cls]++;
    if (++collected < VOTE_PREDICTIONS) break;                          // collect 5
    /* winner = non-clean class with the most votes */
    if (event_votes >= MIN_EVENT_VOTES) {                               // at least 3
        announce(winner);
        holdoff = HOLDOFF_S;  state = HOLDOFF;                          // 20 s
    } else {
        state = IDLE;
    }
    break;

case HOLDOFF:
    if (--holdoff <= 0) state = IDLE;
    break;
  1. Idle. Two non-clean predictions in a row open a vote. One alone is ignored.
  2. Voting. Five more predictions are collected, which lands them in the part of the response the model was trained on. With at least three non-clean votes the leading class is announced; otherwise it was a blip.
  3. Hold-off. For 20 seconds nothing new is announced while the sensor recovers, so one event is reported once.
  4. announce prints >>> EVENT: <class> and calls buzzer_beep with the class index as the count: once for breath, twice for alcohol, three times for smoke. Expect it 6 to 8 seconds after the stimulus starts.

Check: the board agrees with the PC

A model that works in Python and fails on the board is nearly always a preprocessing mismatch, and watching live output will not reveal it. The replay test sends recorded windows of raw voltage to the board, which runs them through its own normalisation and model, and compares the output bytes with the PC's:

.venv/bin/python tools/replay.py --count 300
300 windows: same class on 300/300, identical outputs on 300/300, largest output difference 0 of 255
replay_task() 
// PC sends:    R <v0> <v1> ... <v99>\n
// board says:  R,<out0>,<out1>,<out2>,<out3>
while (count < MODEL_WINDOW) {
    char *end;
    float value = strtof(cursor, &end);
    if (end == cursor) break;
    v[count++] = value;
    cursor = end;
}
if (count != MODEL_WINDOW || classify(v, out) < 0) { printf("R,error\n"); continue; }
  1. The same classify() the live loop uses, so the test exercises the real code path.
  2. Raw voltages go in, not features, so the board's own normalisation is part of what is tested.
  3. The PC side uses TensorFlow Lite's reference kernels, which round exactly as the board's library does. The default PC kernels differ by one step now and then, which was enough to flip 2 of 80 borderline windows.

The improvement loop

The board runs one firmware at a time. To add data, flash the logger, record a new session, then retrain and flash the classifier again.

cd firmware/data_logger && idf.py -p /dev/ttyACM0 flash
.venv/bin/python training/preprocess.py && .venv/bin/python training/train.py && .venv/bin/python training/convert.py
cd firmware/inference && idf.py -p /dev/ttyACM0 flash monitor

Only model_data.cc changes, so that last rebuild takes seconds. Once three sessions exist, train.py switches by itself to holding out whole sessions, and its figure becomes one you can trust.

idf.py: command not found

ESP-IDF is not activated in that terminal. Run . ~/.espressif/tools/activate_idf_v6.0.1.sh first.

A tool cannot open /dev/ttyACM0

Another program holds the port. Close the ESP-IDF monitor (Ctrl+]) or any other tool that is still running.

plot.py fails with "No module named matplotlib"

That terminal has ESP-IDF activated, which switches python3 to ESP-IDF's own environment. Use a terminal without it, or .venv/bin/python.

collect.py or replay.py says "No data" or "No answer"

The board is running the other firmware. collect.py needs the data logger; replay.py needs the inference firmware.

It works in Python and is wrong on the board

Run the replay test. If the outputs differ, model_data.cc is stale: run convert.py, then rebuild and flash.

The clean-air voltage is different every day

That is normal for MQ sensors, and the reason every window is normalised to its own start.
